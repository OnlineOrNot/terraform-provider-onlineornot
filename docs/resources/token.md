# onlineornot_token (Resource)

Manages an API token. Configuration changes replace the token. The secret is only returned on creation and is stored in Terraform state.

The provider credential needs `API_TOKENS` `EDIT` for creation/deletion (which implies `READ` for refresh). Requested grants must be a subset of the parent API token's grants; `EDIT` permits delegating `READ` or `EDIT`, while `READ` cannot delegate `EDIT`. Use a separate management credential, not the token being managed.

## Expiration and replacement

Omit `expires_at` and leave `never_expires = false` to use the API default of **365 days from creation**. `expires_after` records the actual date, so refresh does not recalculate this default. Set `expires_at` for a specific UTC timestamp, or explicitly set `never_expires = true` for no expiration. Do not combine those settings.

The API has no update endpoint. Editing the name, grants, or expiration settings destroys and recreates the token. Replacement issues a new secret and revokes the old token. Consider `create_before_destroy` and coordinate consumers to avoid interruption; Terraform cannot automatically update external consumers. Revoked or expired provider credentials may prevent refresh or destruction.

## Secret handling

`token` is sensitive and computed, returned only on creation, and retained during refresh. **Sensitive does not encrypt state**: protect Terraform state, saved plans, backups, and outputs with access controls and encryption. Do not commit them or enable verbose logs around credentials.

Import retrieves metadata only: the secret remains null and cannot be recovered. Keep the existing secret separately or deliberately replace the resource to issue a new one. Deleting an already-absent token succeeds; a read returning HTTP 404 removes it from state. Authentication and other API errors do not remove state.

## Example Usage

```terraform
# The provider key needs API_TOKENS EDIT and every grant delegated below.
# Omitting expiry uses the API default of 365 days from creation.
resource "onlineornot_token" "monitoring" {
  name = "Monitoring automation"
  grants = [
    { scope = "UPTIME_CHECKS", permission = "READ" },
    { scope = "STATUS_PAGES", permission = "READ" },
  ]
  expires_at = "2030-01-01T00:00:00Z"
  # For no expiration, omit expires_at and explicitly set never_expires = true.
}

output "monitoring_token" {
  value     = onlineornot_token.monitoring.token
  sensitive = true
}
```

## Import

For an existing expiring token, set `expires_at` in configuration to its `expires_after` value returned by the API. The initial import reads that expiration into state; matching configuration does not replace the credential. For a non-expiring token, configure `never_expires = true`. Import cannot infer whether an existing expiry originally used the API default. Tokens created by this provider with omitted `expires_at` continue to preserve that omission on refresh.

```shell
# Import by token ID, NOT the secret. Import cannot recover the secret.
terraform import onlineornot_token.monitoring a1b2c3d4
```
