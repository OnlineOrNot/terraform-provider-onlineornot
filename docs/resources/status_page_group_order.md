# onlineornot_status_page_group_order (Resource)

Owns the complete display order of **all component groups on a status page**. The provider credential needs status-page read and edit permissions.

## Example Usage

```terraform
# IDs below must include every current member of this scope.
# Prefer references to managed component/group IDs to establish dependencies.
resource "onlineornot_status_page_group_order" "layout" {
  status_page_id = "pageAAAA"
  group_ids      = ["groupAAAA", "groupBBBB"]
}
```

## Complete membership and ownership

- Supply every current ID in this scope **exactly once**, in the desired display order. Partial lists, duplicates, IDs from another scope, and omitted members are rejected before an ordering update. An empty list is valid only when the scope is empty.
- Use **one ordering resource per scope**, including across Terraform states. Do not manage the same layout with multiple resources or concurrent dashboard/API edits.
- Ordering only changes display ranks: it never creates, deletes, or moves components or groups. Group membership remains owned by `onlineornot_status_page_component.group_id`. Ungrouped ordering excludes grouped components; group ordering does not order the components inside those groups.
- Reads follow every list page and preserve the API's result order, detecting dashboard reorders, additions, removals, and membership moves. Refresh exposes actual membership; apply rejects a stale or incomplete configured list rather than deleting unlisted members.
- Prefer component/group resource ID references to establish dependencies. **Staged applies may be necessary for component deletion or group moves**: Terraform can otherwise update ordering before the membership change completes. Temporarily remove the ordering resource (destroy only relinquishes ownership), apply membership changes, then reintroduce ordering with the complete new list. Existing ordering can also be imported after membership settles.
- Membership validation and the rank update are not atomic. Avoid concurrent layout/membership changes while applying; inconsistent pagination or post-update order returns a diagnostic so you can reconcile and retry.

## Destroy and missing parents

Destroy only relinquishes Terraform ownership. It leaves the remote layout unchanged and does not reset ranks or delete any component/group. Changing page identity replaces this ownership resource with the same non-destructive behavior.

A confirmed parent page HTTP 404 removes ownership from state. Authentication, permission, and other API errors preserve state and report an error. An existing empty scope remains managed.
